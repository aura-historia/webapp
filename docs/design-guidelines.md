# Design Guidelines

## Design identity

The look is **Catalogue × Terminal**: an auction catalogue's serif, parchment and oxblood, crossed with a data terminal's mono labels, hairlines and exact numbers. Calm, legible, never salesy. The source of truth is the Aura Historia Design System (tokens) and the Aura Historia Redesign (screens).

Core signals:

- Two grounds: parchment (light) for catalogue sections; ink (dark) for the hero, dealer section and footer. `oxblood` is the brand, `brass` the accent.
- Typography: `Newsreader` (`font-serif`) for headlines, object titles, numbers and the wordmark; `Geist` (`font-sans`) for running copy and UI; `Geist Mono` (`font-mono`) for uppercase labels, eyebrows and tags.
- Hairlines, not shadows: cards carry `shadow-ring`; drop shadows only for floating elements (`shadow-search`, `shadow-menu`).
- Calm layouts with generous whitespace, strong hierarchy, and restrained motion.
- Professional UI behavior: predictable, accessible, responsive, and fast.

Put a new board on the page of the screen it belongs to; a component used by several screens goes on Shared.

For every component you are asked to build or change:

1. Read its board in the Redesign file and its card in the design system before writing code.
2. Board missing (a state, a variant, a picker, an empty or error state): add a board to the Redesign file first, built only from design-system tokens and components, then implement it.
3. Change request: update the board first, then the code, in the same task, so both match at the end.
4. A change to tokens, type styles or a shared component is a design-system change: update the design system, then `src/styles.css` or the component, together.
5. Only touch boards for the components in scope; do not redesign or "tidy" other boards or components.
6. Mention the boards you added or changed in the commit or PR description.

## Tokens and styling

Use the token system in `src/styles.css`, which mirrors the design system's `tokens.css`:

- Colours: `surface`, `surface-raised`, `surface-sunken`, `surface-bar`, `image-ground`, `ink`, `ink-secondary`, `ink-muted`, `ink-placeholder`, `oxblood`, `on-oxblood*`, `brass`, `brass-ink`, `brass-light`, `sand`, `signal-live`, `line`, `line-subtle`, `line-strong`, `chip-on-image` (e.g. `bg-surface-raised`, `text-ink-muted`, `border-line`).
- On parchment, brass is a fill, never text; use `brass-ink` for brass-coloured text. On ink, oxblood is only a fill carrying `on-oxblood` text.
- Type styles: `text-display-hero`, `text-display-section`, `text-display-figure`, `text-display-rail`, `text-title-lg|md|sm`, `text-stat`, `text-question`, `text-object-title(-sm)`, `text-wordmark`, `text-lead`, `text-body(-lg|-sm)`, `text-meta`, `text-button`, `text-price`, `text-eyebrow`, `text-kicker`, `text-label`, `text-tag`. Each sets size, line height, weight and tracking; pair it with `font-serif`, `font-sans` or `font-mono`. Display sizes are fluid.
- Radius grows with the object: `rounded-xs|sm|thumb|md|field|lg|panel|figure|card|pill`.
- Spacing and layout: `--space-*` (design spacing), `max-w-content` (1280px), `--page-gutter`, `--section-padding`.
- Dark ground: wrap a section in `data-theme="dark"` (and `data-theme="light"` to return); all tokens and utilities below it switch. `.dark` maps to the same values.
- Legacy shadcn tokens (`bg-background`, `bg-card`, `bg-surface-container`, `text-primary`, `text-muted-foreground`, `border-border`, …) remain as aliases onto the new palette for existing components. Prefer the design-system tokens in new or redesigned components.
- Fonts are self-hosted via Fontsource and imported in `src/styles.css`; the latin Geist and Newsreader (upright and italic) files are preloaded in `src/routes/__root.tsx`. Keep those preloads in sync when changing font files.
- Do not hardcode new colors unless an exact asset/brand requirement exists. Add reusable tokens instead.
- Preserve dark-mode compatibility when touching colors or contrast.
- Use `cn` from `@/lib/utils` for class composition when variants/conditionals are needed.
- Keep Tailwind class composition close to existing component style.

## Components

- Reuse `src/components/ui/*` primitives before creating new primitives.
- For new shadcn components, use the latest shadcn CLI pattern from `.cursorrules`: `pnpx shadcn@latest add <component>`.
- Keep shared primitives generic in `src/components/ui`; put product/domain behavior in feature or domain components.
- Use existing typography components in `src/components/typography` for headings where appropriate.
- Maintain named exports unless a local file pattern already uses default exports.

## Navigation

- `Header` in `src/features/app-shell` picks the variant: the landing page gets `SiteHeader` (88px, site sections and calls to action, from 1024px), every other page gets the sticky `AppNavBar` (64px, global search, from 640px), and smaller screens get `MobileHeader` with the full-screen ink `MobileMenu`.
- Site sections live in `navigation/navigationConfig.ts`; account shortcuts live in `AccountMenu` and `MobileMenu`.
- `Footer` sits on the ink ground: wordmark, tagline and contact, then the Discover, Partners, Comparisons and Company groups from `footer/Footer.data.ts` (the brand takes the first, wider column from 1024px; from 768px it has its own row above four equal link columns; one-at-a-time disclosures on phones), social links and `LocaleSwitch` (language, currency, units; shared with `MobileMenu`). Each switch opens a `PreferencePicker`: a parchment popover listbox with a mono title, an oxblood check on the selected row and, for currencies, a search field (design board "Nav · Locale pickers").
- The landing header lies transparently over the ink hero (`tone="overlay"`); it is sticky on phones and scrolls away with the hero from 1024px.

## Fallback pages

- The router's default not-found and error pages (`NotFoundPage`, `ErrorPage` in `src/features/app-shell/components/fallback/`) follow the boards "Fallback · Page not found" and "Fallback · Something went wrong" on the Shared page. Both sit between the normal header and footer and share `FallbackPage`: a mono brass eyebrow ("Error 404", "Unexpected error"), a serif display headline with its closing phrase in `<em>`, a lead and two 44px pill actions, plus a generic icon: a 200px disc beside the text from 1024px, a 56px disc above the eyebrow below it. Raised disc for a missing page, oxblood disc for an error.
- Not found offers Search objects and Go to homepage. Error offers Try again, which resets the query error boundary, invalidates the router and shows "Trying again…" with a spinner until it settles, and Go to homepage.
- Routes with their own not-found panel (for example a provider that does not exist) keep it; the fallback pages are only the defaults.

## Landing page

- The landing page follows the Redesign's chapters: hero (headline, lead, search, stat strip), Latest acquisitions, II The opportunity, III The platform, IV How it works, V Pricing, VI For dealers, VII Questions, and the oxblood newsletter band. Chapter headings use `SectionHeading` (mono Roman-numeral eyebrow, serif headline whose closing phrase is `<em>`); grounds come from `LandingSection` and alternate parchment and ink.
- Latest acquisitions and any other live inventory load after mount (see `docs/landing-page-prerendering-guidelines.md`). Use real listings only; the design system's sample photos are stand-ins for mockups and never marketing imagery.
- Figures need a cited source. Do not ship bracketed placeholders; leave the element out until the figure is confirmed.
- A source line says how current a figure is: a report by publisher, title and edition ("Art Basel & UBS Art Market Report 2026"), a count by publisher and data year ("IBISWorld US 2024 · IBISWorld Europe 2025"). A figure's label gives the year it describes (2025 sales, from the 2026 report). When a new edition comes out, update every place the figures appear (the opportunity headline, figure and `MARKET_SEGMENTS` shares, and the about page's first difference row) and the source line together, in the Redesign boards and every locale.
- The hero stat strip (`HeroStats`) shows indexed dealers, auction houses, auction platforms and marketplaces, then live objects and countries, from the public overview API, loaded after mount with a skeleton of the same height. It does not show the total of sources or the languages. Figures are exact and grouped in the page language; live objects shorten from a million ("1.8M"). Labels are pluralised by the figure ("1 Country", "18 Countries"). From 1024px the six sit in one ruled row as wide as the headline, so the strip keeps a single row's height under the two-line "art and antiques" headline; from 640px a ruled 3 × 2 grid; phones a compact 3 × 2 grid with smaller figures. Labels may wrap to two lines; the German "Auktionshäuser" and "Auktionsplattformen" carry soft hyphens so they never overflow their cells. Labels reserve two lines, so the skeleton and the loaded strip have the same height. A failed read leaves the strip out rather than showing placeholders or zeros.
- Pricing is designed and built but stays hidden on the landing page until paid plans launch.
- Pricing (`PricingSection`) shows the fixed Stripe catalogue amounts in `PricingSection.data.ts`, one per supported currency for both paid plans (a missing currency is a type error, not a "coming soon" state). Yearly shows the annual charge divided by twelve, at the currency's charge precision (none for JPY and KRW), with the monthly price struck through. When any price runs to nine characters or more ("1 399 TWD", "4.158,33 HUF"), all three step down a size together so they stay inside the cards. Feature rows state the backend entitlements: active search alerts and watchlist objects, monthly match notifications, permitted alert criteria, and matching evidence (title and description; text and up to one image on Pro; text and up to four images plus detailed search instructions for AI-Agent matching on Ultimate). They make no delivery-time or priority promises. The platform chapter's first card presents those search instructions as an Ultimate search-alert feature, not as an autonomous agent, and the search-alerts card makes no "be first" timing claim.
- VI For dealers (`DealersSection`) lists four numbered rows: Partner Connect for Shopify, Partner Connect for WooCommerce® (from the WordPress plugin directory), the custom integration and the partner dashboard. A mark sits beside each arrow: Shopify's official Shopping Bag in full colour, the WordPress W Mark in `ink` (both in `components/icons/PlatformIcons.tsx`, copied from the brands' own files), and Lucide `Braces` and `ChartLine` at the arrow's 1.6 stroke for our own tools. Marks are decorative and keep their colours while the row turns brass. WooCommerce appears by name only, after our product name and with ® ("Partner Connect for WooCommerce®"): Woo's trademark guidelines allow no Woo or WooCommerce logo without a licence and ask for an Automattic attribution, so the shared trademark line closes the list. The two external rows open in a new tab and say so to screen readers. States and locale lengths follow the board "Landing · VI Dealer integration rows".

## Product search

## About page

- The about page follows the Redesign's About page and reuses the landing page's `LandingSection`, `SectionHeading` and `FaqItem`. It is written so people and AI search can lift plain facts from it: the lead states what Aura Historia is in one sentence, chapter headlines say literally what follows ("What Aura Historia *does.*"), and the FAQ repeats the essentials.

## Comparison pages

Comparison pages (`features/comparison`, `/{lng}/compare/<slug>`) follow the Redesign's Comparison Pages boards and are written to be quoted by people, search engines and AI answers. Every page is the same template filled from a **definition** (`ComparisonDefinition` in `config/comparisonDefinition.ts`; Barnebys' is `config/barnebysComparison.ts`, Artsy's `config/artsyComparison.ts`, Invaluable's `config/invaluableComparison.ts`, 1stDibs' `config/firstDibsComparison.ts`, LiveAuctioneers' `config/liveAuctioneersComparison.ts`, Catawiki's `config/catawikiComparison.ts`, eBay's `config/ebayComparison.ts`, the art price databases' `config/artPriceDatabasesComparison.ts`) and its copy in the page's own namespace (`compareBarnebysPage.*`). Strings every page shares (the nav label, "Last reviewed", the status label, "Other comparisons") live in `comparison.*`.

- The definition holds the slug and route, the competitor's name (never translated), the namespace, the meta key, the review date, the quick verdicts, the advantage cards (key and icon), the scorecard rows, the optional `sources`, `alerts` and `together` chapters, an optional `statusNote` (one dated sentence a primary source supports, such as an insolvency, a change of operator or a combination with another company), the FAQ items with their anchors, the Article `about` topics and the positioning line for the cross-link block. Verdicts are `aura`, `competitor` or `tie`: an oxblood pill with a check for Aura Historia, an outlined pill for the competitor, and a quieter outline with an equals sign for a tie (use it where both offer the same thing, or where the two are complementary rather than rivals, and say which in the verdict line, for example "Complementary"). In the scorecard the verdict line carries the check or the equals sign the same way.
- One h1, then chapters that are each a `section` with a stable id and an h2: `#summary`, `#respect`, `#advantages`, `#scorecard`, `#sources`, `#alerts`, `#together`, `#faq`, `#verdict`. Summary, respect, advantages, scorecard, FAQ and verdict are always there; `sources` (source types), `alerts` and `together` ("How the two fit together", for a competitor a reader may use next to the search, such as a venue for bidding) appear only when the definition has them and take their titles from the page's copy, while their ids stay the same. Headlines close with an italic phrase (`<em>` in the translation); on ink and oxblood it is set in brass-light.
- An ink hero (brass-light eyebrow, serif headline, lead, the search call to action and See the scorecard, the "Last reviewed" date) sits beside the quick answer: a raised `section` (not an `aside`) with the best-for rows and a sentence that leads with a bold "Verdict:". Below the hero an "On this page" bar is **derived from the definition**: every chapter but respect, with chapter numerals beside the links on phones (an arrow for the verdict). It is a ruled list on phones and one row that sticks under the nav bar from 640px.
- Then I Summary (parchment), II Respect (raised, centred heading over two columns, and with `statusNote` a ruled line with a mono "Status" label and one dated, factual sentence about the competitor), III Advantages (ink, numbered columns: one, two from 720px, four from 1080px), IV Scorecard, V Source coverage (raised: the ruled source list beside four outcome cards), VI Alerts or Together (parchment, one narrow column: a title and two paragraphs; both chapters share the layout and a page may have either or both, `alerts` first), VII Questions (VIII when a page has both) (raised, numbered and ruled, every answer always visible with a stable id such as `#faq-alternative`) and the final verdict on oxblood. Numerals shift when an optional chapter is left out.
- The scorecard is one real `table` with a visually hidden caption and `th scope="col"`/`scope="row"`. From 1024px it reads as three columns (criterion with its verdict, the competitor, Aura Historia; the competitor header is `headers.competitor` in the page's copy) and scrolls inside its card when narrow; below that each row stacks its cells under their column labels without becoming a list.
- **Other comparisons** (`#other-comparisons`): a quiet parchment band after the article, before the footer. It lists the other pages in `COMPARISON_REGISTRY` (`config/comparisonRegistry.ts`) as internal links: "Aura Historia vs <name>" in serif with the positioning line under it, three columns from 1080px, two from 720px. The current page is left out, and the band is not rendered when no other comparison is published.
- "Last reviewed" is each page's fixed ISO day in its own file (Barnebys: `BARNEBYS_COMPARISON_LAST_REVIEWED` in `config/barnebysComparisonReview.ts`; Artsy: `ARTSY_COMPARISON_LAST_REVIEWED` in `config/artsyComparisonReview.ts`; Invaluable: `INVALUABLE_COMPARISON_LAST_REVIEWED` in `config/invaluableComparisonReview.ts`; 1stDibs: `FIRST_DIBS_COMPARISON_LAST_REVIEWED` in `config/firstDibsComparisonReview.ts`; LiveAuctioneers: `LIVE_AUCTIONEERS_COMPARISON_LAST_REVIEWED` in `config/liveAuctioneersComparisonReview.ts`; Catawiki: `CATAWIKI_COMPARISON_LAST_REVIEWED` in `config/catawikiComparisonReview.ts`; eBay: `EBAY_COMPARISON_LAST_REVIEWED` in `config/ebayComparisonReview.ts`; art price databases: `ART_PRICE_DATABASES_COMPARISON_LAST_REVIEWED` in `config/artPriceDatabasesComparisonReview.ts`). Change it only after re-checking the page's claims against the sources listed in its definition file, never from the clock or the build. It is formatted in the page language in UTC and fills both `<time datetime>` and the Article `dateModified`.
- The route head (`lib/comparisonHead.ts`) sets the meta, canonical and hreflang and publishes JSON-LD from `lib/comparisonStructuredData.ts`: an `Article` (plain-text headline, description, `dateModified`, `about` topics) and an `FAQPage` from the same strings the page shows. No breadcrumb, no Review or AggregateRating. Calls to action stay internal; never link to a competitor. Record each claim's source (URL and access date) as a comment in the definition file, not on the page.

## Layout and responsive behavior

- Design mobile-first and test responsive breakpoints mentally when editing JSX/class names.
- Avoid layout shifts from late-loading client-only values. Prefer SSR-safe loader/context data when possible.
- Ensure focus states, keyboard paths, aria labels, and semantic elements are preserved.
- Prefer clear empty/loading/error states over blank areas.
- Use component-matching skeletons for loading states

## Motion and imagery

- Motion should feel premium and purposeful, not flashy.
- Respect reduced-motion expectations where interactions become substantial.
- Every notification-alert toggle uses `ToggleBellIcon` (`src/components/common`): a decaying swing as alerts turn on, a small settle as they turn off, never on first render, and off under reduced motion.
- Every infinite list ends with the shared `ListLoaderRow` (`src/components/common`): a hairline row with a spinner (and an optional mono progress counter) while the next page loads, then an oxblood check and the all-loaded message. The check pops in and its tick draws 500 ms after the row scrolls into view, once per mount, so readers actually see it; under reduced motion it shows at once.
- Decorative images need `alt=""` and `aria-hidden="true"`; informative images need localized alt text.
- Remote image changes should consider performance, dimensions, and cumulative layout shift.
